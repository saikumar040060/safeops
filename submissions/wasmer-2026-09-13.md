# Submission draft: SafeOps / Wasmer Containment Lab

## Short pitch

An allowed tool can still be compromised. SafeOps checks the proposed action; our new
Wasmer integration contains the code that executes it. The demo shows both layers
working, with an auditable result for each step.

## Description

AI-agent authorization is not enough when a permitted tool reads unintended files or
opens an unexpected network connection. Our hackathon contribution adds a Wasmer-backed
analysis tool to SafeOps' existing permission, policy, risk, approval, and audit pipeline.
Small CSV inputs run in a real Python WASIX package through wasmer-sdk 0.2.1. No host
directories are mounted and guest networking is disabled. Unknown capability fields
are rejected, and failures never fall back to host execution.

The reproducible demonstration covers a successful calculation, a blocked injected
ticket, a denied capability, a contained adversarial tool fixture, and an approval gate
followed by authorized execution. In the containment case, positive controls confirm
that the host can read a synthetic secret and connect to a live loopback listener; the
guest cannot do either. Results and ordered audit events are provided with the code.

## What was built today

New: the Wasmer tool, fixed guest workloads, capability probes with host positive
controls, bounded worker execution, gateway regression tests, five-case integration
demo, result report, and captioned evidence walkthrough.

Pre-existing: SafeOps core, dashboard, policy/risk/approval/audit engines, and previous
integrations. Baseline commit: e0a27bc. We request evaluation of today's extension;
we do not claim the entire platform was built during this event. Organizer acceptance
of this scope and remote demo arrangements are still unconfirmed.

## Results

389 backend tests passed; 5 real integration scenarios passed locally. The driver and
approval actor are scripted. The data and network target are synthetic/locally owned.
The walkthrough presents recorded results, not a live LLM session or a live screen capture.

## Three-minute live demo script

0:00–0:20 — Problem: authorization cannot contain a compromised implementation.

0:20–0:45 — Show today's files and disclose the existing platform.

0:45–1:30 — Run `python integrations/wasmer/demo.py`. Explain the successful CSV,
known injected source block, and permission denial.

1:30–2:15 — Open `results.json`. Show the host positive controls and the two guest
denials. Explain: no mounts, no network; the worker process is not the sandbox.

2:15–2:40 — Show approval-required audit events and the scripted approver's successful
execution. Distinguish this from claiming a real human participated in this run.

2:40–3:00 — Show regression tests and limitations. Close: “Check what the agent asks
for. Contain what the tool can actually do.”
